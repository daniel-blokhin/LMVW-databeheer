# Portfolio positioning

Suggested repository description:

> Python geospatial data pipeline for housing-plan monitoring: API ingestion, standalone data-quality validation, authoritative/spatial record linking, and verified SQL Server-ready exports.

Possible CV wording, to be adjusted to your own verified contributions:

> Developed a modular Python pipeline integrating housing-plan deliveries with BAG, BRK and DSO/RP sources, including CRS-aware spatial joins, record-level quality gates, provenance and referentially validated database exports.

A technical interview walkthrough should begin with a failing synthetic record, follow its source row into a quality finding/quarantine record, then contrast it with an accepted plan linked to a BAG parent outside the polygon. Explain why the area key is not a unique plan ID and why a spatial DSO match is not a substantive legal confirmation. Finish by verifying the export manifest and running an offline replay test.

The strongest demonstrated areas are data engineering, geospatial analytics, quality assurance, API integration and reproducibility. There is no need to invent a trained model or completed dashboard to call the project valuable. Show the tests, boundary decisions and known gaps rather than claiming it is an entire production platform.

Do not claim sole authorship of a collaborative original project, live production verification not performed, certified compliance, or performance at a scale that has not been measured. Distinguish the tender-demo implementation, this refactor and future visualisation work.
